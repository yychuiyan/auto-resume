# 简历投递助手

Chrome 扩展，分两个独立版本：

| 版本 | 目录 | 说明 |
| --- | --- | --- |
| **1.0** | `extension-v1.0/` | 搜索页抓取后批量投递简历，支持 BOSS、智联 |
| **2.0** | `extension-v2.0/` | 上传 Word 简历，AI 解析匹配规则后自动搜岗并批量投递，支持 BOSS、智联、前程无忧 |

两个扩展可同时安装，互不影响。

当前 `extension-v2.0` 版本：**2.0.3**（见 [manifest.json](extension-v2.0/manifest.json) 与 [CHANGELOG.md](CHANGELOG.md)）。

## 安装

1. 打开 `chrome://extensions/`
2. 开启右上角「开发者模式」
3. 点击「加载已解压的扩展程序」
4. 选 `extension-v1.0/` 或 `extension-v2.0/`
5. 修改代码后需在该页重新加载对应扩展

也可从 [Releases](https://github.com/yychuiyan/auto-resume/releases) 下载 `extension-v1.0` / `extension-v2.0` 压缩包，解压后再按上面步骤加载。

## 1.0 批量投递简历

点扩展图标打开弹窗。在对应平台搜索页搜好职位后，切到对应 Tab 抓取再投递。

### BOSS 直聘

| 步骤      | 操作                                |
| --------- | ----------------------------------- |
| 1. 搜职位 | 在 BOSS 搜索页输入关键词搜索        |
| 2. 抓取   | 🔵 BOSS Tab → **从搜索页抓取职位**  |
| 3. 投递   | 设置数量、间隔 → **开始批量打招呼** |

- 使用平台默认招呼语
- 自动调用搜索 API 获取 securityId，跳过详情页
- 触发风控自动停止并弹出 BOSS 页面

### 智联招聘

| 步骤      | 操作                               |
| --------- | ---------------------------------- |
| 1. 搜职位 | 在智联搜索页输入关键词搜索         |
| 2. 抓取   | 🔴 智联 Tab → **从搜索页抓取职位** |
| 3. 投递   | 设置数量、间隔 → **开始批量投递**  |

- 自动识别附件简历并投递
- 使用平台默认招呼语
- 支持后台运行（关闭弹窗后继续）

### 1.0 其它说明

- 每个 Tab 下方显示今日成功投递数，每天 0 点归零
- 关闭弹窗后日志保留；垃圾箱按钮清除日志
- 投递中工具栏显示红色取消按钮
- Chrome 需保持打开；各平台需已登录且有默认简历
- 投递间隔建议 3～5 秒，过快可能触发风控

## 2.0 AI 简历匹配投递

点工具栏图标打开侧边栏（不是弹窗）。先上传简历并解析，再按平台匹配、投递。

### 准备

1. 在侧边栏填写 DeepSeek API Key 并保存（默认 `deepseek-v4-flash`）
2. 上传 `.docx` 简历 → **解析简历**
3. 核对职位、城市、薪资（最低月薪）、公司规模、学历、方向选择 / 排除词、技能、工作词
4. 点 **保存匹配规则**（解析不会覆盖已选薪资/规模）

画像只存在本机 Chrome，不会上传到本仓库。删除简历后需重新上传才能匹配。

### 匹配与投递

| 平台        | 怎么找岗位                   | 怎么投                           |
| ----------- | ---------------------------- | -------------------------------- |
| BOSS / 智联 | 按画像职位 + 城市自动搜 2 页 | 后台批量打招呼 / 投递            |
| 前程无忧    | 读取**当前搜索页**列表       | 后台复制搜索页点申请，本页不跳走 |

流程：粗筛（职位名 / 技能 / 工作词）→ 精排读 JD → 按数量和间隔投递。列表里每条岗位可单独「忽略」，被忽略的既不投递、下一轮匹配也跳过（见[忽略名单](#忽略名单不想投的岗位剔出去)）。

自动排除：派遣/代招、校招、猎头、已投、已忽略、不可选、职位名含实习/兼职。前程另排除网申（`applyType=1/2/3`）。看不出薪资或规模的岗位会留下。

真正会硬性淘汰岗位的规则：派遣/外包、校招实习、学历不符、薪资或规模低于阈值、城市不符、已投/去重、**已忽略**、**命中排除词**，以及**筛选模式下的方向不符**。

三端都是「粗筛 → 精排」两段，精排淘汰的岗位即使精排整体为 0 条也**不会**被回退回结果里（回退只补精排没判到的岗位，比如详情页被风控中断），否则硬规则会被回退悄悄绕过。

### 方向（AI 生成，可编辑）

方向**完全由 AI 按简历内容生成**，不限定行业：软件测试、交互设计、财务、新媒体运营都能用。没有任何内置方向词表。

解析简历时 AI 会给出两组东西：

| 字段 | 内容 | 作用 |
| --- | --- | --- |
| `directions` | 2~6 个「这份简历真正在做的方向」，每个方向带 4~10 个专属关键词 | 下拉里可选可勾的方向 |
| `otherDirections` | 4~6 个「同领域但这份简历不符合」的相邻方向及其关键词 | 只参与判定，把你不要的岗位排除掉；**不出现在方向下拉里**（只出现在排除词面板的只读区） |
| `excludeKeywords` | 4~8 个「命中即排除」的行话/黑话 | 排除词面板里的可编辑项，判定时压过方向白名单 |

每个方向都带自己的关键词，例如：

```js
交互设计 → 交互设计、UX、用户体验、原型、Axure、信息架构
用户研究 → 用户研究、用户访谈、可用性测试、问卷、Persona
```

关键词必须是**有区分度的专有词**。`工程师`、`测试`、`开发`、`设计`、`产品`、`运营`、`经理`、`自动化`、`资深` 这类泛词会被自动剔掉——留着它们会让同族方向互相抢，`座舱自动化测试工程师` 就会被「自动化」判成自动化测试。

#### 下拉里怎么操作

- 候选 = **AI 从简历解析出的** + **你手工新增/改名的**
- 点方向名字 → 就地改名（回车/失焦保存，`Esc` 取消）；改成已存在的名字会合并，并保留关键词
- 点名字右边的 **数字/`词`** 按钮 → 就地编辑这个方向的关键词（逗号分隔）。只填同义词即可，方向名本身永远算一个关键词
- 标灰的项表示**还没设关键词**，只能按名字字面匹配，同义写法认不出
- 每项右侧 `×` 删掉该方向（连同它的关键词）
- 底部输入框回车或点「添加」新增方向，新增项立即勾选，关键词默认为名字本身
- 候选上限 40 项，名字最长 12 字；重新点「解析」会以 AI 的新结果为准

#### 筛选开关

- 勾着「全部（不限方向）」→ `directions` 存空数组 → 不筛选，所有方向都参与排名
- 取消「全部」→ 只保留勾选方向的岗位，**未勾选方向直接淘汰**
- 直接取消某一项也会自动进入筛选模式；一项都不剩会退回「全部」
- AI 解析完成后默认**全部勾上**，也就是默认只匹配简历解析出来的那几个方向

#### 判定规则（两层否决）

```txt
第一层：命中排除词？
  命中 → 淘汰（计入「已排除关键词」，明细里记命中词）
──────────────────────────────
第二层：方向识别
命中分 = 标题命中权重更高 + 其余文本命中
分最高者 = 这个岗位的方向
一个关键词都没命中 → 认不出 → 放行（不猜，宁多勿漏）
方向已勾选         → 放行
方向未勾选         → 淘汰（计入「方向不符」）
```

平局依次比：**命中词在标题里更靠前**（中文岗位名是「领域限定 + 职能」，`座舱自动化测试` 里靠前的 `座舱` 才是区分方向的词）→ 命中词更长 → 方向名更长。

| 情况                                    | 结果                              |
| --------------------------------------- | --------------------------------- |
| 勾着「全部」（不限方向）/ 未配置        | 不筛选（排除词也不生效）          |
| 命中排除词                              | **淘汰**（`exclude`，压过白名单） |
| 识别出方向，且在勾选里                  | 保留                              |
| 识别出方向，但不在勾选里                | **淘汰**（`direction`）           |
| 认不出方向（只命中泛词 / 没有可读文本） | 保留                              |

**泛名不参与判定**：`测试工程师`、`资深测试` 这类去掉通用词后什么都不剩、又没配关键词的方向会被跳过，否则它会凭名字更长把同类岗位全吞掉。配了专属关键词的方向不受此限（`产品经理` 名字里含泛词，但它的关键词有区分度，照常参与）。

**新增方向但不勾选 = 自动排除**。识别池是「所有候选方向 + AI 给的相邻方向」，不是只有勾选的那些——没勾的方向必须也能被认出来，才能判成不符淘汰掉，否则它会跟勾着的同族方向抢词、被吸走放行。所以：

| 操作 | 效果 |
| --- | --- |
| 新增「硬件测试」，填了 `座舱/车载/台架/HIL`，**不勾** | 这类岗位被淘汰，日志写「方向不符: 硬件测试」 |
| 同一个方向**勾上** | 立刻变成保留方向 |
| 新增了但**没填关键词** | 只能拦住标题里字面写了「硬件测试」的岗位，`座舱自动化测试工程师` 认不出 → 放行 |

注意：新增方向默认是**勾上**的（默认意图是「我要投这个」）。想拿它当排除项，新增完把勾去掉再点匹配。

手填的关键词和 AI 给的一样参与识别；方向名本身永远算一个词（AI 漏写方向名时，直写方向名的岗位也不会漏），但 `自动化测试` 这类纯泛名不会自动带上，避免和同族方向抢词。

匹配开始时日志会先回显本次生效的方向：

```txt
方向 3 个: 软件测试/自动化测试/接口测试（其余方向一律排除）
```

显示 `方向 不限` 就说明当前不筛选。改了勾选但没点「保存规则」也没关系，点「读取简历并匹配职位」会先把当前勾选静默落库再匹配。

#### 排除词（否决名单）

「方向选择」右边是**排除词**，它和方向选择是两套独立的东西：

|          | 方向选择                  | 排除词                    |
| -------- | ------------------------- | ------------------------- |
| 类型     | 方向名白名单              | 自由词黑名单              |
| 数据     | `directions`              | `excludeKeywords`         |
| 作用     | 认出的方向不在勾选里 → 拦 | 岗位文本里出现这个词 → 拦 |
| 判定顺序 | 第二步                    | **第一步（优先级更高）**  |

- 排除词可以是任何词：`车载`、`座舱`、`驻场`、`外包`、`台架`、`HIL`、`BMS`…
- 判定范围是**岗位名 + 技能 + 标签 + 简介 + JD 正文**，大小写不敏感，命中即拦
- 一旦命中，就算它的方向在「方向选择」里勾着也照样拦——排除词压过白名单
- 两边彻底解耦：删一个排除词不会动方向勾选，取消方向勾选也不会产生排除词

**选「全部（不限方向）」时排除词整体置灰、不生效**——用户显式说了「全都收」，这时候再拦就自相矛盾。要排除先取消「全部」，勾上具体方向。

**解析简历时 AI 会自动生成 4~8 个排除词并直接生效**，LLM 按简历推断「另一行」的行话（做软件测试的简历会给 `车载/座舱/台架/HIL/CAN/BMS`）。不满意可以：

- 点词直接改名，点 `×` 删除，在底部输入框添加（一次粘贴多个词，逗号/空格/顿号分隔都行）
- 下拉下半段的「未勾选方向」是**只读区**：它只是解释「这些方向正被白名单挡掉」，点「转为排除词」才把该方向的关键词批量并进排除词，升级成文本级拦截

**重新解析不会覆盖你的改动**：

- 手加的排除词会保留
- AI 新一轮给的词会追加进来
- 你删掉的词不会被 AI 加回来（记了墓碑）
- 手改过的方向关键词不会被 AI 冲掉；手取消的方向勾选也不会被重新勾上

#### 被挡住时，日志会告诉你是谁挡的

```txt
粗筛样例: 座舱自动化测试工程师 0(职位0/技能0/工作0/命中:车载/已排除关键词) | …
已排除 已排除关键词 3 条、方向不符 5 条
方向不符明细: 「车载」3 条（座舱自动化测试工程师、车载测试工程师、台架测试工程师）；「硬件测试」2 条（…）
被方向/排除词筛掉 8 条（「车载」、「硬件测试」）：方向名补勾就能放行；如果上面列的是排除词，去「排除词」里删掉它即可。
```

- `命中:xxx` 是单个岗位的判定结果，最多列 5 条样例；命中排除词时 `xxx` 是**那个词**，方向不符时是**方向名**
- 「方向不符明细」按条数从多到少排，两个原因合并统计：每个键最多带 3 个岗位名举例，最多列 6 个键
- 「已排除关键词」和「方向不符」在汇总里分开计数，明细里合并展示
- 精排拿到 JD 后会**再判一次**，淘汰时写成 `精排淘汰(方向不符) xxx → 判成「硬件测试」，没勾它`
- 想放行：方向不符就补勾方向名；是排除词就去「排除词」里删掉，或者点词改名

`excludeKeywords` 的判定包含 JD 正文，所以粗筛阶段（还没取 JD）只按标题/技能/标签拦一次，精排拿到 JD 后会再补一次——JD 里写了 `车载` 的岗位在精排被拦，粗筛阶段可能已经放过。

三端（BOSS / 智联 / 前程）格式一致，前程还会额外标出公司名。

#### 老画像怎么办

老版本存的 `软件 / 硬件 / AI测试` 会原样当作自定义方向名保留，关键词回退成名字本身。这时方向只在「字面含这两个字」的岗位上生效，其余岗位一律认不出 → 放行，看起来就像筛选没生效。此时匹配日志会提示：

```txt
方向 2 个: AI测试/软件（其余方向一律排除） · 但这些方向都没有关键词，只能按名字字面匹配，认不出的岗位会全部放行。请点「解析」重新生成关键词
```

**重新点一次「解析」**即可拿到 AI 生成的关键词和相邻方向（`otherDirections`），方向识别精度会明显提升。不想重解析，也可以点方向右侧的「词」手填。

要加新方向，直接在侧边栏新增并填关键词，不需要改代码。

### 公司黑名单

工作关键词下方有一个可折叠的「公司黑名单」，用来挡掉外包 / 人力 / 代招公司。三个平台通用，判定规则是**公司名包含即过滤**（`北京中软国际信息技术有限公司` 会被 `中软国际` 挡掉）。

- 默认名单来自 `extension-v2.0/blocklist/outsource-companies.txt`（一行一个，`#` 开头是注释）
- **第一次打开侧边栏**时，这份文件会被导入到 `chrome.storage.local.company_blacklist`，之后匹配只看 storage
- 也就是说内置名单和自定义名单**是同一份，随便增删改**：
  - 输入框回车 / 点「加入」新增
  - 点名字就地改名（回车保存，`Esc` 取消）
  - 点 `×` 移除
  - 「恢复默认」重新载入内置 txt 的内容（会覆盖当前名单）
- 「导出 outsource-companies.txt」把当前名单（含你改过的条目）下载成 txt，可以直接覆盖 `blocklist/outsource-companies.txt` 分发给别人

> 浏览器扩展**不能写自己包内的文件**，所以名单的"保存"落在 storage 里；txt 只负责两件事：首次导入的默认值，以及导出后的备份 / 分发。改了名单不用重新加载扩展，匹配时即时生效。

匹配日志里会回显本次生效的家数：

```txt
公司黑名单 18 家
```

### 最低月薪怎么判

薪资按**岗位区间上限**比较，不是下限：

- 设 `12K`，岗位 `6-12K`、`11-12K`、`12K以上` 都**保留**（上限 ≥ 12K）
- 岗位 `6-11K`、`8千-1万` 才**过滤**（上限 < 12K）
- 面议 / 看不出薪资 → 一律保留

单位逐个数字识别，所以 `6千-1.2万` 是 6K～12K、`1-2万` 是 10K～20K、`20-30万/年` 折算成约 16.7K～25K；`6-12K·13薪` 的 13 是发薪月数，不会被当成上限。`100-150元/天`、`30元/时` 这类日薪/时薪会按 21.75 天/月、8 小时/天折算成月薪，避免被当成 100~150K 放行。

老画像兼容：`['软件']` 这类旧值会展开成对应方向，「大类 + 子方向」的两级对象会自动拍平成一维名字。老数据里分不清来源的候选会被清掉——没解析到、又不是你手工加的内置项不再显示。

### 2.0 其它

- 侧边栏随当前招聘站自动切 Tab；日志三端共用，切 Tab 不清空
- **「简历与匹配规则」卡和「API 设置」面板的展开/收起会被记住**（`ui_resume_open` / `ui_api_open`）：切到智联或前程、关掉侧栏再打开、重启浏览器都保持上次的样子。多个 tab 的侧栏同时开着时，一边点了另一边会立刻跟着变，不用再点一次

- 今日已投只计成功数，按平台分记，每天归零
- 投递中可取消；间隔建议 3～5 秒

### 去重与计数规则

每个平台各存一份**本机已投名单**（`chrome.storage.local` 的 `applied_ids_boss` / `applied_ids_zp` / `applied_ids_w51`），匹配后的下一轮直接跳过名单里的岗位。侧边栏显示「本机去重 N」，可点「清空」重建。前程还额外记一份「匹配已跳过」（`w51_matched_ids`，换搜索关键词会自动重置），面板上的「本机去重」是两份的并集；点「清空」会一起清掉。

| 情况                       | 计数    | 写入名单 | 今日已投 |
| -------------------------- | ------- | -------- | -------- |
| 真正投出                   | ✅ 成功 | 是       | +1       |
| 平台返回已投过（重复）     | 🔁 重复 | 是       | 不加     |
| 风控、超时、缺参等失败     | ❌ 失败 | 否       | 不加     |

平台侧的判定才是权威，本机名单只用于提前过滤、少发请求：

- BOSS：搜索接口返回 `friend`，或打招呼返回「已经和对方沟通过」
- 智联：申请接口返回 `repeated` 数组，或消息含「重复投递 / 已申请过」
- 前程：列表按钮文案变成「已申请 / 重复申请」

「今日沟通已达上限」「操作太频繁」这类属于配额或风控，不算重复，不会写入名单，下一轮仍会重试。

名单上限 1 万条/平台（约 600 KB 合计），超出丢弃最旧的记录。

### 二次匹配为空怎么办

连续投递几轮后，本机名单会盖住搜索池里的大部分岗位，再点「读取简历并匹配职位」容易只剩 0 条。现在会自动处理：

1. **加深翻页**：前 2 页**既没投过、也没被忽略**的岗位不足 40 条时，自动翻到最多 12 页（`SEARCH_PAGES_DEEP`）；某页没有新岗位就停，说明池子翻到底了。BOSS、智联都生效。
2. **换关键词兜底**：粗筛为 0 且被「已投/已沟通」或「已忽略」挡掉过岗位时，用画像里没用过的职位名、补「工程师」的变体、额外技能再搜一轮（最多 3 个词、2 页，不做二次深翻），合并去重后重新粗筛。同理只在前程保留「本页无新岗自动翻页」的原有逻辑。
3. **明确提示**：日志会写清是「搜索接口返回 0 条」（未登录/风控/城市没岗位）、「全在本机已投名单」或「全被标记忽略」（可点对应「清空」），还是「被排除规则挡掉」（看「已排除」明细）。

真想把投过的岗位再看一遍，点侧边栏的「清空」重置本机去重即可。

### 忽略名单：不想投的岗位剔出去

匹配列表里每行标题旁有个「忽略」按钮（平时隐藏，鼠标移到该行才出现，位置在标题和状态列之间，右对齐）：

- 这条岗位**本轮不投**，也**不会出现在后续匹配结果里**（匹配阶段直接按「已忽略」排除，日志会写「已忽略 N 条（本轮跳过）」）
- 该行标题加删除线、变灰，按钮变成常显的「恢复」；点「恢复」立刻重新参与投递
- 名单存在 `ignored_ids_boss` / `ignored_ids_zp` / `ignored_ids_w51`，上限 1 万条/平台，重启浏览器/重载扩展都还在
- 面板上显示「已忽略 N」，点旁边的「清空」把该平台忽略名单整个清掉，之前忽略的岗位会重新出现

**已投优先于忽略**：投过的岗位即使后来被忽略，统计里仍算「已投/已沟通」，不会影响去重口径。

### 列表里的投递状态

匹配列表每行标题右边有一列状态，投递过程中实时变化，投完也能一眼看出哪条成功、哪条失败：

| 状态 | 含义 | 忽略按钮 |
| --- | --- | --- |
| 待投递 | 还没发过，本轮会投 | hover 出现「忽略」 |
| 投递中 | 正在发这一条（蓝色呼吸） | 不显示 |
| 已投递 | 本次成功，或本机已投名单里有它 | 不显示 |
| 已沟通 | 平台提示「已沟通过 / 已投过」，记入去重但不计今日已投 | 不显示 |
| 已跳过 | 前程的「简历投递 / 页面跳转」这类不可直投，记入去重 | 不显示 |
| 失败 | 本次失败（超时 / 平台报错），红字；再点一次投递会补投它 | hover 出现「忽略」 |
| 已忽略 | 被手动忽略，本轮不投、后续匹配也跳过 | 常显「恢复」 |

列的位置是「标题 → 忽略 → 状态 → 分数」：状态列按 3 个字的宽度定死（32px，左右各留 1px），文字居中，2 字的「失败」也落在列中间，分数列不会左右跳。

判定优先级：投递中 → 已投递/已沟通（本轮结果）→ 已投递（名单）→ 已忽略 → 已跳过 → 失败 → 待投递。所以投过的岗位即使本轮标记过失败，显示的仍是「已投递」。

已投递 / 已沟通 / 已跳过 / 投递中这四种**不给忽略按钮**（位置留白，右侧分数列不会位移）：这些岗位已经进去重名单，忽略它没有任何效果。只有待投递和失败能忽略——反复失败的岗位可以先按住不投。历史遗留的「既已投又被忽略」的行仍保留「恢复」，方便撤销。

状态只活在本轮：重新匹配、清空去重、清空忽略名单都会把上一轮的结果一起清掉，新列表从「待投递」开始。

### 批量投递的拦截规则

「开始批量投递 / 开始批量打招呼」不再是点了就发，而是先按当前名单状态过一遍检查：

| 状态 | 表现 |
| --- | --- |
| 还没点「读取简历并匹配职位」 | 拦下，状态栏提示「请先匹配岗位」，日志说明要先拿列表 |
| 列表里的岗位都已投成功 | 按钮置灰，按钮下方写明「本批 N 条已全部投递成功，重新匹配或点「清空」重置去重」 |
| 列表里的岗位都被忽略 | 按钮置灰，提示可点「已忽略」旁的「清空」，或在列表里点「恢复」 |
| 部分投递成功 / 部分失败 | 按钮可用，只把**还没投成功**的岗位按数量取前 N 条重发，已成功的不会重投 |
| 全部投完的混合情况 | 按钮置灰，提示「已全部投递或忽略（已投 X、忽略 Y）」 |

按钮下方的提示行会实时显示「待投 K/共 N 条（已投 X、失败 Y、忽略 Z 已剔除）」，数量输入框的语义是**这次要投几条还没投的岗**，不会被已投/忽略的占位。前程的「简历投递 / 页面跳转」这类跳过也会记入去重，避免同一批岗每次点投递都白跑一遍。

### BOSS 限流 code=37：同一页面只能搜一轮

BOSS 的 `search/joblist.json` 吃的是页面加载时发的令牌，**同一个页面文档里只够搜一轮**：第一次点「读取简历并匹配职位」正常，紧接着再点，所有请求都返回 `code=37`、`n=0`，手动刷新页面才能恢复。

现在扩展自动处理，不用再手动刷新：

1. **预判**：搜完会把当前页面的 `performance.timeOrigin` 记进 `chrome.storage.local`（单键 `boss_used_page`，内含 tabId）。下次点同一个页面（timeOrigin 相同 ⇒ 文档没换过）就先刷新，并等到 `timeOrigin` 真的变了、页面 `complete`、再停 1.5 秒让页面自己的列表请求跑完，然后才搜。
2. **补救**：万一标记没对上（换过 URL、页面是你手动刷新的），搜出 0 条且带 `code != 0` 时同样刷新重试一次。同一次点击最多刷一次——刷完还是 `code=37` 就不再刷第二遍。
3. **仍然不行**：日志写「刷新后仍是 code=37，这是账号级频率限制，等一分钟再点」，说明不是页面令牌的问题，只能等。

日志长这样：

```txt
这个页面已经搜过一轮，BOSS 接口会限流(code=37)，刷新页面拿到新令牌后重试
页面已刷新，重新搜索
```
